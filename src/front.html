How to Use These Notes

Front matter  •  reading paths, conventions and the visual key

These notes replace slide-by-slide study with a single continuous explanation. Each topic is introduced with the problem it solves, then the rule, then a worked example on small tables that you can check by hand. Nothing important from the source has been dropped; the source's fragments have been re-ordered into a sequence where each idea rests on the one before it.

The visual key

Colour is used with a fixed meaning throughout, exactly as a technical figure should. Learn the key once and every later diagram reads faster.

Definition Blue panels carry a formal definition you should be able to reproduce almost word for word.
Explanation Teal panels add reasoning, background or a bridge to the next idea.
Worked step Amber panels show intermediate reasoning: a dry run, a probe sequence, a closure computation.
Common mistake Red panels flag a genuine error or a trap that costs marks.
Correct result Green panels mark a verified output, a successful decomposition, or a fact worth memorising.
From the source Violet notes record where the source material is ambiguous, incomplete or internally inconsistent, and say plainly what has been done about it.

Conventions used in the code

All database code in these notes is Oracle SQL and Oracle PL/SQL, the dialect of the source material. SQL keywords appear in upper case, identifiers in lower case, and every PL/SQL block ends with a slash (/) because that is how the blocks are submitted at the SQL*Plus prompt. Output blocks are shown immediately after the program that produces them, and were derived by tracing the program statement by statement. Where a program uses a substitution variable (&num), the value typed at the prompt is shown in the transcript exactly as SQL*Plus echoes it.

A word on the source

The source material is a set of lecture notes and slides: it is accurate in substance but fragmented, sometimes repeats a definition twice with different wording, and occasionally leaves a table image described only by a caption. These notes keep the source's terminology and examples, supply the missing tables explicitly, and add new illustrative examples only where the source gives none — such additions are always labelled “illustrative example”. Chapter 36 lists exactly what was covered and what was not.

Honest scope limit — please read

The course outcome list mentions transaction processing, recovery techniques, triggers, procedures and packages. The supplied PDF contains no lecture content for those topics: it covers only keys, functional dependencies, normalization, denormalization, database security, PL/SQL control structures, cursors and views. Those topics are therefore not written as chapters here, because doing so would mean inventing material and presenting it as if it came from your course. They are listed in Chapter 36 as a documented coverage gap.

What these notes add beyond the source

Three things, all clearly marked. First, diagrams: the source's figures exist only as captions such as “Output:”, so every table, relationship, dependency and flow has been redrawn as a vector figure with a number and caption. Second, explicit tables: where the source says “the above table” without showing it, the rows have been reconstructed from the surrounding text and are labelled as reconstructed. Third, a question bank (Chapters 32–34) built strictly from the source's own examples. No new DBMS theory has been imported from outside the supplied material.
